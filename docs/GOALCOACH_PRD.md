### 1. Strategic Alignment & Current State Audit

#### 1.1 The Alignment Verdict

The core domain model, spaced repetition math, and vector database architecture in the codebase are **fundamentally aligned** with the original proposal. The recent terminal and FastAPI outputs confirm that the PydanticAI layer, retrieval tools, and OpenRouter/Ollama dual-model failover are functioning as specified.

However, exposing this functionality primarily through a `/tutoring/chat` endpoint and a Streamlit chat UI created an architectural drift toward a **stateless conversational chatbot**.

#### 1.2 Pivot from "Chatbot" to "Directed Pedagogical Engine"

GoalCoach is modeled after structured, interactive platforms like **HelloChinese** and **Brilliant**, rather than an open-ended conversational bot:

```
   TRADITIONAL CHATBOT (Anti-Pattern)                GOALCOACH (Target Architecture)
 ┌────────────────────────────────────┐            ┌────────────────────────────────────┐
 │  User is forced to ask:            │            │  System inspects state and directs:│
 │  "What should I learn today?"      │            │  1. Scheduled Spaced Review        │
 │                                    │            │  2. Targeted Remedial Drill        │
 │  Stateless, prompt-driven,         │            │  3. Progressive Next Concept       │
 │  fragmented, unmeasured.           │            │                                    │
 └────────────────────────────────────┘            │  Closed, measured, deterministic.  │
                                                   └────────────────────────────────────┘

```

The AI does not wait for user prompts. It operates as an embedded **evaluator, explainer, and scheduler** inside an interactive, multi-modal learning client.

### 2. Product Vision & User Experience Architecture

#### 2.1 Core User Journey

The product implements a closed-loop learning cycle: **Goal $\to$ Plan $\to$ Teach $\to$ Grade $\to$ Update $\to$ Adapt $\to$ Re-plan**.

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ 1. Onboarding   │ ──► │ 2. Daily Plan   │ ──► │ 3. Interactive  │ ──► │ 4. Rubric-Based │
│ & Diagnostic    │     │ Generation      │     │ Practice Modal  │     │ Grading Engine  │
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
                                                         ▲                       │
                                                         │                       ▼
                                                ┌─────────────────┐     ┌─────────────────┐
                                                │ 6. Next Session │ ◄── │ 5. State &      │
                                                │ Dynamic Routing │     │ Retention Decay │
                                                └─────────────────┘     └─────────────────┘

```

1. **Deterministic Directing:** Upon login, the user is presented with their active daily plan: a balanced queue of **Review items**, **Remedial items**, and **New concepts**. Free navigation through the curriculum is constrained by prerequisite gating.


2. **Multi-Modal Practice:** Lessons present structured exercises (character decomposition, pinyin tone discrimination, sentence reordering, audio shadowing, and freeform text input) rather than open conversational dialogue.
3. **Embedded Coaching:** The AI tutor acts as an on-demand coach (the "Panda Coach") accessible via a slide-over drawer to explain mistakes or break down grammar rules.


4. **Transparent Retention Tracking:** Progress is tracked using an honest retention metric ($\sum \text{Mastery} \times \text{Retention}$) where unreviewed concepts visually decay over time.



#### 2.2 Key User Interface Modalities (React/Vite Client)

Based on the provided frontend design specifications:

* **Top Status Bar:** Tracks current retention score, daily streak, review queues, and direct access to the daily plan.


* **Daily Plan View:** Displays the prioritized task queue generated by the deterministic orchestrator.


* **Serpentine Curriculum Roadmap:** A progressive skill-tree path (HelloChinese style) showing concepts as nodes (Locked, Unlocked, Learned, Mastered).


* **Duolingo-Style Practice Modal:** Renders exercises (MCQ, Cloze, Sentence Builder, Pronunciation, Freeform) with native audio feedback and instant evaluation.


* **Interactive Pinyin Lab:** An acoustic visualization matrix displaying initials, finals, 4 pitch contours, and tone sandhi rules with audio demonstration.


* **Slide-over Coach Drawer:** An auxiliary side panel powered by the RAG Teaching Agent to answer contextual questions without leaving the active exercise.

#### 3.2 Dual-Model Inference Strategy

To preserve the $50/week OpenRouter budget while guaranteeing demo resilience, all agent interactions are routed through a provider-neutral gateway:

| Provider | Target Model | Role & Scope |
| --- | --- | --- |
| **OpenRouter (Primary)** | `qwen/qwen-2.5-72b-instruct` or `deepseek/deepseek-chat` | Complex semantic sentence evaluation, open-ended grading, multi-turn explanation.

 |
| **Ollama (Local Fallback)** | `unsloth/gemma-4-12b-it-GGUF` | Zero-network offline fallback automatically invoked upon timeout or API error.

 |
| **Deterministic Rule Engine** | Pure Python string normalization & AST regex | Fast-path grading for multiple choice, cloze, and exact reference matches (<1ms).

 |

### 4. Functional Specifications

#### Module 1: Deterministic Workflow Orchestrator

The top-level controller uses pure Python state evaluation without LLM intervention:

```python
def route(state: LearnerState) -> NextAction:
    # Priority 1: Uninitialized or modified goal
    if state.goal is None or state.goal_changed:
        return NextAction.PLAN_GOAL
    
    # Priority 2: Concepts requiring spaced review (next_review_at <= now)
    if state.review_due():
        return NextAction.PLAN_REVIEW
        
    # Priority 3: Missing, invalid, or exhausted daily plan
    if state.active_plan is None or state.active_plan.status != PlanStatus.ACTIVE:
        return NextAction.REGENERATE_PLAN
        
    # Priority 4: Default active execution loop
    return NextAction.TEACH

```

#### Module 2: Prerequisite-Aware Planning Core (GCO-14)

The planner prioritizes tasks deterministically and allocates time based on `daily_available_minutes`:

1. **Review Items:** Scheduled concepts where $R(t) \le 0.70$ or `next_review_at <= now`.


2. **Remedial Items:** Concepts with recorded errors in `error_profile` where mastery $< 0.60$.


3. **New Concepts:** Next unmastered concepts in the HSK1 sequence, gated by prerequisite relationships. A new concept is **blocked** unless all its prerequisites have achieved $\ge 0.70$ mastery and $\ge 1$ evidence count.



#### Module 3: Multi-Modal Grading Engine (GCO-13)

Answer evaluation uses a tiered hybrid pipeline:

```
User Answer Submission
          │
          ├── [Exact Match with accepted_answers] ──► Return 1.0 (Bypass LLM)
          │
          └── [Freeform Text / Open Synthesis]
                    │
                    ▼
          PydanticAI Grader Agent (OpenRouter / Ollama Gemma 4)
          ├── 1. Grammatical Correctness (Syntax, SVO, Particles: 吗, 了, 呢)
          ├── 2. Semantic Precision (Instruction satisfaction)
          └── 3. Pragmatic Appropriateness (Natural register)
                    │
                    ▼
          Strict Pydantic v2 Output: GradingResult
          ├── scores: RubricScores
          ├── passed_gates: bool (both Grammar & Semantics >= 0.70)
          └── detected_errors: list[ErrorCode]

```

#### Module 4: Mathematical Retention & Progress Model

Retention decay and overall progress are calculated using deterministic formulas:

$$\text{Retention: } R(t) = R_0 \cdot e^{-\lambda \cdot \Delta t}$$

$$\text{Overall Progress: } P = \frac{\sum_{i=1}^{N} (w_i \cdot M_i \cdot R_i(t))}{\sum_{i=1}^{N} w_i}$$

* $M_i \in [0.0, 1.0]$: Mastery score, adjusted by $+0.25$ on pass and $-0.10$ on fail.


* $R_i(t) \in [0.0, 1.0]$: Decayed retention score based on elapsed days $\Delta t$.


* When exercises are completed, updates to $M_i$, $R_i$, and `error_profile` are processed asynchronously in the background and persisted to `goalcoach.db` (SQLite WAL mode).

### 5. API Interface Contract (FastAPI)

The API specification connects the React frontend to the backend services:

```yaml
openapi: 3.1.0
info:
  title: GoalCoach Pedagogical Engine API
  version: 1.0.0
paths:
  /api/v1/learners/{learner_id}:
    get:
      summary: Fetch complete learner state, next recommended action, and progress
      responses:
        "200":
          content:
            application/json:
              schema:
                type: object
                properties:
                  state: { $ref: "#/components/schemas/LearnerState" }
                  nextAction: { type: string, enum: [plan_goal, plan_review, regenerate_plan, teach] }
                  overallProgress: { type: number }

  /api/v1/learners/{learner_id}/plan:
    post:
      summary: Deterministically generate or regenerate the active daily plan
      responses:
        "200":
          content:
            application/json:
              schema:
                type: object
                properties:
                  plan: { $ref: "#/components/schemas/DailyPlan" }
                  state: { $ref: "#/components/schemas/LearnerState" }
                  nextAction: { type: string }

  /api/v1/curriculum/concepts:
    get:
      summary: Retrieve all HSK1 concepts with prerequisite metadata
      responses:
        "200":
          content:
            application/json:
              schema:
                type: array
                items: { $ref: "#/components/schemas/CurriculumConcept" }

  /api/v1/answers:
    post:
      summary: Submit exercise answer for rubric grading and state update
      requestBody:
        content:
          application/json:
            schema:
              type: object
              required: [learner_id, exercise_id, answer]
              properties:
                learner_id: { type: string, format: uuid }
                exercise_id: { type: string, format: uuid }
                answer: { type: string }
      responses:
        "200":
          content:
            application/json:
              schema:
                type: object
                properties:
                  gradingResult: { $ref: "#/components/schemas/GradingResult" }
                  state: { $ref: "#/components/schemas/LearnerState" }
                  overallProgress: { type: number }
                  nextAction: { type: string }

  /api/v1/tutoring/chat:
    post:
      summary: Contextual pedagogical help drawer (PydanticAI Agentic RAG)
      requestBody:
        content:
          application/json:
            schema:
              type: object
              required: [learner_id, message]
              properties:
                learner_id: { type: string, format: uuid }
                message: { type: string }
      responses:
        "200":
          content:
            application/json:
              schema:
                type: object
                properties:
                  response:
                    type: object
                    properties:
                      reply: { type: string }
                      grammar_points: { type: array, items: { type: string } }
                      suggested_practice: { type: string, nullable: true }
                  provider: { type: string }

```
