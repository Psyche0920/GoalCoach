# Project management

This directory converts the proposal and senior engineering verdict into an executable four-week delivery system.

## Documents

- [`roadmap.md`](roadmap.md): weekly capability milestones and exit criteria.
- [`backlog.md`](backlog.md): prioritized implementation work.
- [`risks.md`](risks.md): active technical and delivery risks.
- [`responsibilities.md`](responsibilities.md): proposed ownership boundaries.
- [`definition-of-done.md`](definition-of-done.md): shared completion standard.
- [`demo-checklist.md`](demo-checklist.md): final validation and presentation readiness.
- [`meeting-notes/`](meeting-notes/README.md): decision-oriented meeting records.

## Working rules

- Update the backlog and risk register at least at each sprint review.
- Store permanent technical decisions as ADRs, not only in meeting notes.
- Link work items to a weekly capability and a testable acceptance criterion.
- Do not mark an AI feature complete without evaluation evidence.
- Keep personal data, secrets, and unlicensed learning content out of Git.
